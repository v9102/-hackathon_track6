Demo Video Script - Autonomous Agentic Resume Tailoring (Goal -> Decision -> Action -> ... -> Outcome)

GOAL: Build a truthful, fully autonomous resume tailoring agent that matches a candidate to a role while NEVER fabricating experience. Every logged decision maps to a real, evidence-backed change; rejected ideas are recorded as rejected.

DEMO PART 1 - The default profile (honest accept): 
1. Run: python3 -m app.main run
2. The agent parses the JD into a role knowledge base, parses all 3 candidate resumes (Shaunak, AI/ML Engineer, DevOps Engineer) from PDFs, and evaluates the original resumes (ATS %, relevance %, factuality %, format %).
3. The planner decides the best action. For the default role profile the original Shaunak resume already meets acceptance, so the agent records 0 decisions and accepts it as-is: final_status = accepted, factuality 100%, a verified final PDF is produced.
4. Show the run directory storage/runs/<run_id>/ with state.json (full audit trail), final_report.txt, and tailored_resume_final.pdf.

DEMO PART 2 - A JD that forces adaptation (surface / reject / verify):
1. Run: python3 -m app.main run --jd data/sample_jd.txt
2. This full-stack JD lists skills the resume supports (Python, TypeScript, ...) and skills it does NOT support (Kafka, Kubernetes, Redis).
3. DECISION - iteration 1: 'Surface required skills into existing project bullets'. ACTION: the agent modifies a COPY of the resume, surfacing authentic subtitle evidence into the WorkflowOS project bullet ("Python", "TypeScript"). INTERMEDIATE RESULT: bullet diffs and before/after recorded; evaluation re-run.
4. ADAPTATION - iterations 2-3: the agent PROPOSES adding 'Kafka' then 'Kubernetes'. Each is REJECTED because the candidate's original resume provides no authentic evidence for it; the skill joins the unsatisfiable set and is never re-proposed.
5. RE-EVALUATION + FINAL VERIFICATION: the final PDF is rendered via pdflatex, verified to be a valid artifact with all required sections, and the final scores are recorded (factuality 100%, format 100%).
6. FINAL OUTCOME: max_iterations_reached with a clean 4-decision audit trail (2 accepted surface actions, 2 rejected probes, each with evidence and before/after text).
7. Show the final reproducible run output and highlight that factuality never drops below 100% because unsupported skills are refused.

WHY IT IS AGENTIC, NOT HARD-CODED:
- Autonomous goal pursuit: the loop chooses accept / surface / probe from the live evaluation.
- Tool interaction: pdftotext, LaTeX rendering, PDF verification, JSON state persistence.
- Decision making: each decision picks a target and records evidence, before/after diffs, and evaluation deltas.
- Adaptation: rollback on regression; unsatisfiable skills are tracked so ideas are never retried pointlessly.
- Verification: real PDF artifact checks (exists, required sections, size) and per-iteration re-evaluation.

HONESTY GUARANTEES DEMONSTRATED:
- Skills fabricated into bullets are never allowed: probing Kafka/Kubernetes fails loudly with the reason recorded.
- The default role profile correctly accepts the original resume with 0 decisions - the system refuses to make changes just to look busy.
- Unsupported claims count is always 0 in the final evaluation.
